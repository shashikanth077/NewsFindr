NewsFindr

NewsFindr is an agentic news assistant. It takes a registered customer's email, looks up their stored interests with an LLM-driven SQL agent, searches DuckDuckGo News for current articles, filters them with deterministic rules, and returns the top three with a short summary, the reason each one matches the customer, and the original link.

Groq LLMLangChain 1.xSQLite DuckDuckGo NewsPydantic v2StreamlitGoogle Colab

What it guarantees

Live news
Real search
Every article comes from a DuckDuckGo result fetched at run time. Nothing is generated from training memory.
Attribution
URL from source
Titles, URLs, publishers and dates are copied from search results. The LLM never writes them.
Privacy
Read-only, one row
The database is opened read-only. The agent's query tool only returns the verified customer's row.
Honesty
Snippet-based
Summaries cite only the title and snippet. Allowlisting is a reputation signal, not fact-checking.

The workflow in one line

Email→SQL agent→Profile→Query expansion→ DuckDuckGo News→Filter & rank→LLM review→Top 3 with links

3. Pipeline walkthrough

The workflow has eleven steps. Select a step to see what it does, what it reads and writes, and how it fails. The autonomous / deterministic / LLM tags show who decides.

4. Customer data & the SQL agent

The customer store is a SQLite file. The agent answers one question: which customer owns this email, and what are their interests?

The customers table

ColumnTypeMeaning
idINTEGER PKInternal row id
customer_idTEXT, uniqueBusiness identifier, e.g. NF-1001 for sample customers
nameTEXTCustomer's first name
emailTEXT, uniqueIdentity used for verification. Stored lower-case.
interestsTEXT (JSON list)Specific topics, e.g. ["Artificial Intelligence", "Startups"]
preferred_categoriesTEXT (JSON list)Broad news sections, e.g. ["Technology", "Business"]. Back-filled from interests if empty.
preferred_languageTEXTLanguage for summaries. Default English.
last_updatedTIMESTAMPLast change time

Four layers of control around the agent

LayerControl
InputThe email is validated with a Pydantic model before the agent runs. Malformed input never reaches the database.
ConnectionThe database opens with mode=ro. The agent cannot write.
Schema toolsample_rows_in_table_info=0. The agent sees column definitions only, never sample customer rows.
Query toolA guarded tool replaces the toolkit's unrestricted query tool. It accepts one SELECT, rejects OR, UNION, comments, and write or DDL keywords, requires an email filter, and drops any returned row whose email is different.
OutputThe agent's answer must match CustomerLookupResult. Python then re-reads the row with a parameterized query. That row is the source of truth, and a disagreeing answer is discarded.

How one lookup executes

  1. Validate the email (EmailRequest).
  2. Build an agent with create_agent, tools sql_db_list_tables, sql_db_schema and the guarded query tool, and a structured response format.
  3. Loop: the LLM chooses a tool, LangChain runs it, the result goes back to the LLM. The loop stops after recursion_limit=12 steps.
  4. Structured answer: the LLM returns CustomerLookupResult; LangChain validates it and asks for a retry if it doesn't match.
  5. Cross-check: fetch_customer_record() runs a parameterized query. The status is verified, not_found or invalid_email.
What "autonomous" means here The LLM decides which tool to call, what SQL to write, and when it has enough. That is genuine agent behaviour. Python still enforces the guardrails and makes the final decision about which row is correct.
Example of the trace shown in the app (tool calls, illustrative) 
[user]        Verify this customer email and return the profile: john@example.com
[agent #1]    calls `sql_db_schema` with {"table_names": "customers"}
[tool result] sql_db_schema: CREATE TABLE customers ( ... )
[agent #2]    calls `sql_db_query` with {"query": "SELECT * FROM customers"}
[tool result] sql_db_query: Error: the query must filter on the email column ...
[agent #3]    calls `sql_db_query` with {"query": "SELECT customer_id, ... WHERE lower(email) = 'john@example.com' LIMIT 1"}
[tool result] sql_db_query: {"rows": [ ... one row ... ], "row_count": 1}
[agent #4]    calls `CustomerLookupResult` with {"found": true, ...}

The guard rejected the unfiltered query and the agent recovered on its own. This is the self-correction the guard is designed to allow.

5. Query expansion

A broad interest such as Artificial Intelligence matches explainers and old content. The LLM turns the interests and the customer's request into short, news-oriented queries, one per angle.

Rules given to the LLM

  • 3–9 words, keyword style, aimed at current news.
  • Different angles: announcements, research, funding, regulation.
  • If there is a request, every query stays on it. Otherwise queries spread over the interests.
  • No years, dates, quotes, site: operators or boolean operators.
  • No invented company, product, person or event names.

Post-processing in Python

  • Strip quotes, site: terms and four-digit years even if the LLM included them.
  • Remove case-insensitive duplicates and cap at NUM_EXPANDED_QUERIES (4).
  • If the LLM call fails, fall back to labelled templates. The UI shows fallback so you can see it.
Why this matters for evaluation The method used (llm or fallback) is recorded for every run and displayed in the UI and the notebook, so nobody has to guess whether the LLM or the template produced the queries.

6. News search & filtering

6A. DuckDuckGo News search

  • Uses DuckDuckGoSearchResults with backend="news" and output_format="list".
  • Region wt-wt (worldwide). Safe search: moderate. RESULTS_PER_QUERY = 10.
  • Time window: past week (w). If too few survive, the workflow widens once to past month (m), with a 30-day age limit.
  • Two retries with 2s and 4s back-off on transient errors. "No results" is treated as empty, not as failure.
  • A 1.5s pause between queries to reduce rate-limiting.
  • If every query fails, the run ends with status search_error and says so. It does not present an empty result as "no news".

6B. Filters, in order

#FilterRuleRejection label
1CompletenessTitle and an HTTP(S) URL are requiredmissing title/url
2Duplicate removalCanonical URL (lower-case host, no www., no tracking parameters or fragments) and normalized titleduplicate
3Source allowlistDomain or a parent domain must be in TRUSTED_SOURCESsource not on allowlist
4RecencyOlder than 14 days is rejected. Undated items are kept but scored at 0.2. Dates more than 1 day in the future are treated as unknown.outdated (> 14 days)
5Keyword relevanceLexical score from request, profile and queries; must be at least 0.30. Aliases such as AI ↔ artificial intelligence are included.low relevance

6C. Ranking

keyword_rank = 0.5 × relevance + 0.3 × recency + 0.2 × credibility recency = 0.5 ^ (age_in_days / 3) (undated → 0.2) credibility = allowlist weight (0 if not allowlisted)

The keyword rank is only a coarse pre-filter. The LLM review in Section 9 makes the final choice.

Allowlist ≠ verification Being on the allowlist signals editorial reputation. It does not mean an individual article has been fact-checked, and NewsFindr never labels an article "verified".

9. LLM review & summaries

The LLM works on the top 8 ranked candidates, using only their titles and snippets. It does two things.

9A. Relevance review (one batched call)

  • Each candidate gets an integer score from 0 to 10 for this customer and request, plus a one-sentence reason.
  • Candidates scoring below 6 are dropped.
  • Final ordering: 0.5 × (llm/10) + 0.3 × recency + 0.2 × credibility. The top three are summarised.
  • If the LLM call fails, keyword relevance is used instead and labelled as such.

9B. Grounded summary (one call per article)

  • 2–3 sentences, in the customer's preferred language, using only facts in the title and snippet.
  • A "why this matches you" sentence tied to the request or a specific interest.
  • The model is never asked for URLs, sources or dates. Python copies those from the search result.

Anti-fabrication checks

CheckWhat it does
Content basis noteEvery recommendation says the summary is based only on the title and snippet, because full text is not fetched.
Unsupported-number flagAny number in the summary that does not appear in the title or snippet is listed in a warning.
Fallback textIf summarising fails, the card shows the snippet and says that the summary is unavailable. It does not invent one.

Pick your operating system. Each block can be copied with one click.

1. Open PowerShell in the project folder (the folder that contains app.py).

Get-ChildItem   # you should see app.py, requirements.txt and newsfindr

2. Create and activate a virtual environment

python -m venv .venv
.\.venv\Scripts\Activate.ps1

If activation is blocked: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned, then run the activate line again.

python -m pip install -r requirements.txt

4. Set your key (or skip this and paste it into the sidebar). Use your own key, not the example text.

$env:GROQ_API_KEY = "your_key_here"

python -m streamlit run app.py

14. Troubleshooting

Find your error below. Each entry says what it means and how to fix it.

"export is not recognized as the name of a cmdlet"

export is a bash command. PowerShell uses $env:. Run $env:GROQ_API_KEY = "your_key_here" instead, or paste the key into the sidebar.

"streamlit is not recognized"

The dependencies are not installed in the active environment. Activate the venv, install, then start with python -m streamlit run app.py. Using python -m works even when the script is not on PATH.

.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m streamlit run app.py
".\.venv\Scripts\Activate.ps1 is not recognized"

The .venv folder does not exist in the current folder. Check your location with Get-Location and Get-ChildItem. If you are in the right folder, create the environment with python -m venv .venv.

Activation blocked by execution policy

Run once: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned, then activate again.

"python is not recognized"

Python is not on PATH. Install Python 3.10 or newer from python.org and tick Add python.exe to PATH. Open a new terminal afterwards.

"Could not initialise Groq"

The key is missing, wrong, or revoked, or the model is retired. Check the key in the sidebar. To pick a different model, set GROQ_MODEL in the sidebar's model field.

"Every DuckDuckGo search failed"

Network error or rate limit. Wait a minute and run again. The app reports this status instead of showing "no news", so it is not a content problem.

"No recent articles from allowlisted sources matched this request"

Searches worked, but nothing passed the filters. Try a broader request, or check the allowlist in Section 8. The "Filtered out" tab shows why each article was rejected.

"No customer is registered with this email address"

The email is not in the database. Use a demo address (john@, sarah@ or david@ at example.com) or check the spelling. Lookups are case-insensitive.

Query expansion shows "fallback"

The LLM call failed, usually because of the key, the model, or a rate limit. The app used labelled templates instead. Check the stage log in the "How it worked" tab.

Streamlit shows a browser warning about use_container_width

The current code uses width="stretch". If you see this, you are running an older copy. Pull the latest commit.

15. Autonomy, limitations & future work

What is autonomous

ComponentTypeWho decides
LLMLanguage modelGenerates text. No tools of its own.
SQL agentautonomousLLM chooses tools, writes SQL, decides when done. Guards constrain it.
Query expansionLLMLLM writes queries. Fixed step, Python validates them.
Search, filter, rankdeterministicPython rules only.
Relevance review, summariesLLMLLM scores and writes text. Python selects and attaches links.
OrchestrationdeterministicFixed stage order with error handling at each step.

This is a single-agent system with LLM-powered workflow steps. It is not multi-agent, and it does not decide its own next step beyond the SQL lookup.

Limitations

  • Snippet-only summaries. Full articles are not fetched, so summaries are short and may miss detail.
  • Live results vary. DuckDuckGo results, ordering and date coverage change between runs and regions. Results are not exactly reproducible.
  • Allowlist trade-off. Strict sources raise average quality but exclude good niche and regional outlets.
  • Approximate dates. Some results give relative dates such as "2 days ago", which are converted to approximate times. Undated items rank lower.
  • Lexical relevance pre-filter. Synonyms outside TERM_ALIASES can be missed. The LLM review partly covers this.
  • Quotas. Groq free-tier limits and search rate-limits can slow runs.

Future work

IdeaBenefit
RAG over full article textSummaries from the whole article, where licensing allows
Qdrant vector storeSemantic relevance, near-duplicate detection across outlets, long-term interest embeddings
LangGraph workflowExplicit graph with retries, conditional edges and human checkpoints
Multi-source verificationCluster articles on one event and surface claims corroborated by several outlets
Feedback learningRecord clicks and dismissals in SQLite to learn source and topic weights
Scheduled monitoringDaily email digest and alerts for watched topics
